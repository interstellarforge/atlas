# ADR-0022: Webhooks through the outbox

- Status: accepted
- Date: 2026-10-28

## Context

ATL-77: admins want change events sent to external systems, reliably and verifiably, per project.

## Decision

1. Tables `webhooks` (per project, url, event filter, active, encrypted secret) and `webhook_outbox` (migration 0022).
2. `journal` queues one outbox row per matching active webhook inside the transaction of the change, so a delivery exists exactly when the change committed (same pattern as `mail_outbox`).
3. A scheduler job (every 5 s) sends due rows via `core.DeliverWebhooks`. Retries after 1m, 5m, 15m, 1h, 6h, then the row is marked failed. Finished rows are pruned after 14 days.
4. Each request is signed with `X-Atlas-Signature: sha256=HMAC(secret, timestamp + "." + body)`. The secret is generated by the server, shown once, and stored AES-GCM encrypted with the existing `mail.key`.
5. Sending reuses the SSRF-guarded client of the repository fetcher (`Fetcher.Post`): public addresses only, https only, unless `ATLAS_REPO_ALLOW_PRIVATE` is set. Bodies over 64 KiB are sent without `changes`.
6. Delivery is at least once and per webhook ordered by outbox id only when none fails; receivers must dedupe on `X-Atlas-Delivery`.
7. No MCP tool or UI yet; REST only. Webhook management is project-admin only.
